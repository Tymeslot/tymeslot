# Translating Tymeslot

This directory holds the gettext catalogues for Tymeslot Core — the complete,
self-hosted scheduling product — served by the `TymeslotWeb.Gettext` backend
(`otp_app: :tymeslot`).

`.pot` files are extraction templates and are regenerated by `mix gettext.extract
--merge` — **never edit them by hand**. Only `.po` files carry translations.

Per-language termbases live beside this file as `GLOSSARY.<locale>.md` (e.g.
[`GLOSSARY.de.md`](GLOSSARY.de.md)). Read the one for your language before you start, and add
to it when you settle a term.

> Do not put them in a subdirectory. `mix gettext.merge` treats **every** subdirectory of
> `priv/gettext/` as a locale, and raises `Gettext.Plural.UnknownLocaleError` on anything that
> isn't a valid language tag.

## Workflow

```sh
# 1. Regenerate templates and merge new msgids into every .po
mix gettext.extract --merge

# 2. Translate: fill the empty msgstr entries in priv/gettext/<locale>/LC_MESSAGES/*.po

# 3. Normalise formatting and confirm no msgid drifted
mix gettext.merge priv/gettext --locale <locale>
```

`gettext.merge` must report `0 new, 0 removed` for every domain. Anything else means a
msgid was edited or lost.

> Run both commands from this repository's root, where `mix.exs` lives.

## The rules

**Placeholders are load-bearing.** `%{name}` tokens must be reproduced byte-for-byte.
Never translate, rename, add, or drop one. If the msgid has three placeholders, the msgstr
must contain exactly those three. You *may and should* reorder them to fit the target
language's syntax:

```po
msgid "%{month} %{day}, %{year}"
msgstr "%{day}. %{month} %{year}"
```

A dropped or invented placeholder is a runtime crash, not a typo.

**Never interpolate with `#{}`.** Elixir interpolates before extraction, so the string
becomes a unique literal on every call and can never be translated. Always `%{variable}`.

**Markup and entities pass through verbatim.** `<strong>…</strong>`, `&` (literal, not
`&amp;`), bullets `•`, checkmarks `✓`, and emoji are preserved.

**Fuzzy entries ARE served — they do not fall back.** This surprises people, and it has already
shipped a bug here. After `gettext.extract --merge`, an entry whose msgid changed is fuzzy-matched
against its closest predecessor, the *old* msgstr is copied across, and the entry is marked
`#, fuzzy`. Elixir's Gettext then serves that stale msgstr anyway:

```elixir
# en/LC_MESSAGES/dashboard_admin.po
#, elixir-autogen, elixir-format, fuzzy
msgid "Promote %{email} to admin?"
msgstr "Promote %{email} to admin"     # ← copied from the old msgid, note the missing "?"

Gettext.dgettext(TymeslotWeb.Gettext, "dashboard_admin", "Promote %{email} to admin?", …)
#=> "Promote a@b.c to admin"           # the stale string, not the msgid
```

So after every merge: review each `#, fuzzy` entry, either correct the msgstr or blank it, and
delete the `, fuzzy` flag. Blanking the msgstr is what actually restores the msgid fallback.
`grep -rn fuzzy priv/gettext/` must come back empty before you commit.

**Empty `msgstr` falls back to the msgid.** The `en/` catalogues are intentionally empty.

**Do not edit the file header.** The `##`/`###` preamble is written by gettext. Some tooling
rewrites it as `# `/`# #`; that is corruption, and it has landed in this repo before.

## Plural forms

Most languages have two forms. Ukrainian has three.

```po
# de, fr, it — nplurals=2
msgid "hour"
msgid_plural "hours"
msgstr[0] "Stunde"   # n == 1
msgstr[1] "Stunden"  # everything else, including 0

# uk — nplurals=3
msgstr[0] "хвилина"  # n mod 10 == 1 and n mod 100 != 11
msgstr[1] "хвилини"  # n mod 10 in 2..4
msgstr[2] "хвилин"   # everything else
```

## Domains

Every string declares which area of the app it lives in. Bare `gettext/1,2` is banned and
enforced by `CredoChecks.GettextDomainBoundary`, whose `:domains` param is the single
registry of valid domain names. Using the wrong domain is a silent failure — the string
falls back to English with no error.

A string belongs in `common` only when genuinely shared across two or more areas.

## Do not translate

Brand, product, and provider names, in every language:

> Tymeslot · Stripe · Stripe Checkout · Stripe Connect · reCAPTCHA · Google ·
> Google Calendar · Google Meet · GitHub · Outlook · Microsoft Teams · Zoom · CalDAV ·
> Nextcloud · iCloud · Fastmail · Zimbra · Radicale · mailbox.org · MiroTalk · Keycloak ·
> Authentik · Lemonldap · JavaScript · OAuth · OIDC · SSO · Oban · UTM · Cloudron

Environment-variable and config names, always verbatim: `REGISTRATION_ENABLED`,
`PASSWORD_AUTH_ENABLED`, `STRIPE_SECRET_KEY`, `RECAPTCHA_SITE_KEY`, `GITHUB_CLIENT_ID`,
`OAUTH_*`, and friends.

## Never split a sentence across msgids

The single most damaging mistake. A msgid must be a complete, independently translatable
clause. Word order differs between languages, so fragments assembled at render time cannot
be translated correctly — and the translator sees no context.

```heex
<%!-- WRONG: three msgids, one sentence. "and" is untranslatable in isolation. --%>
{dgettext("auth", "By continuing you agree to our")}
<a href={@terms}>{dgettext("auth", "Terms of Service")}</a>
{dgettext("auth", "and")}
<a href={@privacy}>{dgettext("auth", "Privacy Policy")}</a>
```

German needs the verb near the front — *"Es gelten die …"* — so no assignment of German
text to those three slots produces a correct sentence. Use one msgid with bindings instead,
and let the translator move the links:

```heex
{raw(dgettext("auth",
   "By continuing you agree to our %{terms} and %{privacy}.",
   terms: link_to(@terms, dgettext("auth", "Terms of Service")),
   privacy: link_to(@privacy, dgettext("auth", "Privacy Policy"))))}
```

The same applies to headlines styled mid-phrase. Wrap the whole clause as one msgid and
interpolate the styled span, rather than emitting `"Get in"` + `"Touch"`.

Cosmetic `<br/>` inside a clause should be dropped from the msgid; a `<br/>` that separates
two clauses stays outside them.

## Adding a locale is a promise

`config :tymeslot, :locales` is the single source of truth. A locale listed there appears in the
language switcher, so **every** string a user can reach must exist in it.
`TymeslotWeb.GettextCompletenessTest` holds us to that: it derives its locale list from the
config (there is no allowlist to update) and, for every `.pot` domain in
`apps/tymeslot/priv/gettext`, in every supported locale, checks structure, msgid consistency,
no empty msgstr, and no fuzzy entries. It skips the default locale for the emptiness check — its
msgstrs are intentionally empty, and gettext falls back to the msgid, which is already English.

So the order of work for a new language is: translate every catalogue, *then* add the locale to
the config. Adding it first turns the suite red, which is the point — the alternative is shipping
a language switcher that quietly serves English.

## Locale resolution

For HTTP requests, `LocalePlug` resolves in priority order: `?locale=` query param →
session → `Accept-Language` → `"en"`.

For **emails**, locale is the *recipient's* stored locale (`attendee_locale`), never the
current request's. Always wrap email rendering in `Gettext.with_locale/3`.

Supported locales are declared once, in `config/config.exs` under `config :tymeslot, :locales`.
